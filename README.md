# 오목 알까기

온라인 1대1 오목 게임입니다. 5목을 완성하면 오목이 멈추고, **알까기 한 판**으로 승부를 확정짓습니다.
별도의 서버 프로그램 없이 **GitHub Pages**(정적 파일 호스팅)와 **Firebase Realtime Database**(실시간 동기화)만으로 동작합니다.

이 문서는 서버·배포 경험이 전혀 없는 분도 따라 할 수 있도록 단계별로 설명합니다. 전문 용어가 나오면 그 자리에서 바로 한 줄로 풀어 설명합니다.

---

## 1. 폴더 구성

```
index.html             게임 화면 전체 구조
style.css              디자인
js/
  main.js              화면 전환, 입력 처리, 렌더링 (게임의 중심)
  rules.js              렌주룰 판정 (5목, 금수)
  physics.js            알까기 물리 시뮬레이션
  net.js                 Firebase / 로컬 테스트 모드 공통 통신 계층
  firebase-config.js    Firebase 설정값을 채워 넣는 파일 (처음엔 비어 있음)
database.rules.json     Firebase 보안 규칙
package.json            (배포에는 불필요. Node로 로직을 테스트할 때만 사용하는 설정 파일)
```

**"정적 파일"이란?** 서버에서 미리 프로그램을 돌리는 게 아니라, HTML/CSS/JS 파일을 그대로 브라우저에 전달해서 브라우저가 직접 실행하는 방식을 말합니다. 그래서 GitHub Pages 같은 "파일만 올려두는" 무료 호스팅으로 충분합니다.

## 2. 로컬에서 바로 해보기 (Firebase 없이)

Firebase를 연결하지 않은 상태에서는 자동으로 **"로컬 테스트 모드"**로 동작합니다. 같은 컴퓨터의 브라우저 탭 두 개가 서로 다른 플레이어가 되어 대결할 수 있습니다. (탭을 각각 다른 사람인 것처럼 구분하는 원리: 브라우저의 "세션 저장소"라는 탭별로 독립된 임시 저장 공간을 이용합니다.)

### 실행 방법

1. 프로젝트 폴더에서 터미널(명령 프롬프트)을 열고 아래 명령을 입력합니다. (Python이 설치되어 있다면 바로 됩니다.)

   ```
   python -m http.server 8000
   ```

   이 명령은 "지금 이 폴더의 파일들을 8000번 포트로 열어서 브라우저가 가져갈 수 있게 해줘"라는 뜻입니다. (서버 = 파일/데이터를 요청받아 내려주는 프로그램)

2. 브라우저를 열고 주소창에 아래 주소를 입력합니다.

   ```
   http://localhost:8000/index.html?local=1
   ```

   화면 위에 **"🧪 로컬 테스트 모드"** 배지가 보이면 정상입니다.

3. 닉네임을 입력하고 **"방 만들기"**를 누릅니다. 화면에 4자리 방 코드(예: K7PX)가 표시됩니다.

4. **새 탭을 하나 더 열어서** 같은 주소(`http://localhost:8000/index.html?local=1`)로 들어간 뒤, 다른 닉네임을 입력하고 방 코드를 넣어 **"참가"**를 누릅니다.

5. 두 탭이 각각 흑/백을 배정받고 오목판이 뜨면 성공입니다. 한 탭에서 돌을 두면 다른 탭에도 바로 반영됩니다.

> 서버를 멈추려면 터미널에서 `Ctrl + C`를 누르세요.

### 확인해 볼 것
- 흑 차례에 3-3/4-4/장목 자리를 클릭하면 "금수 자리입니다"라는 안내가 뜨는지
- 5목을 완성하면 화면이 전환되며 "FIGHT!"와 함께 알까기 판이 뜨는지
- 알까기에서 내 알을 누른 채 뒤로 당겼다 놓으면 반대 방향으로 튕겨 나가는지, 상대 탭에도 같은 장면이 보이는지
- 대결이 끝나면 결과 화면이 뜨고, 양쪽에서 "다시 하기"를 누르면 흑백이 바뀌어 새 판이 시작되는지

## 3. Firebase 연결하기 (실제로 다른 컴퓨터끼리 대결하려면 필요)

로컬 테스트 모드는 "같은 브라우저 안"에서만 동작합니다. 친구와 서로 다른 컴퓨터에서 대결하려면, 두 브라우저가 서로의 수를 실시간으로 주고받을 공간이 필요합니다. 이 역할을 **Firebase Realtime Database**(구글이 제공하는 무료 실시간 데이터 저장소)가 담당합니다.

> 이 단계는 Claude Code와 함께 화면을 보면서 한 단계씩 진행합니다. (이 README는 나중에 혼자 다시 설정할 때 참고하는 용도입니다.)

### 3-1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 접속 → 구글 계정으로 로그인
2. **"프로젝트 추가"** 클릭 → 프로젝트 이름 입력(예: `omok-algkagi`) → 애널리틱스는 꺼도 무방 → 프로젝트 만들기
   - 무료입니다. 카드 등록이 필요 없는 기본(Spark) 요금제로 충분합니다.

### 3-2. Realtime Database 만들기
1. 왼쪽 메뉴 **빌드(Build) → Realtime Database** 클릭 → **데이터베이스 만들기**
2. 위치(지역)는 `asia-southeast1`(싱가포르) 등 가까운 지역 아무거나 선택해도 됩니다. (한 번 정하면 나중에 못 바꾸지만, 데모 수준에서는 속도 차이가 크지 않습니다.)
3. 보안 규칙은 **"잠금 모드"**로 시작합니다. (바로 다음 단계에서 규칙을 직접 넣을 것이므로 상관없습니다.)

### 3-3. 보안 규칙 넣기
1. Realtime Database 화면에서 **"규칙(Rules)"** 탭 클릭
2. 기존 내용을 지우고, 이 프로젝트의 `database.rules.json` 파일 내용을 그대로 붙여넣습니다.
3. **"게시(Publish)"** 클릭

   **왜 필요한가요?** 이 게임은 로그인 기능이 없는 데모이므로, 누구나 방 코드만 알면 Realtime Database를 읽고 쓸 수 있습니다. 이 규칙은 "방 코드 형식(영문 대문자+숫자 4자리)이 올바른 경로만" 접근을 허용해서, 최소한의 안전장치 역할을 합니다. 완벽한 보안은 아니라는 점을 알고 사용해 주세요(데모용 범위).

### 3-4. 웹 앱 등록하고 설정값 가져오기
1. 왼쪽 위 **톱니바퀴(프로젝트 설정)** 클릭 → **프로젝트 설정**
2. 아래로 스크롤 → **"내 앱"** → 웹 아이콘(`</>`) 클릭
3. 앱 닉네임 아무거나 입력(예: `omok-web`) → **"Firebase 호스팅도 설정"은 체크 해제** → 앱 등록
4. 화면에 나오는 `const firebaseConfig = { ... }` 값을 복사
5. 이 값을 Claude Code에게 전달하면 `js/firebase-config.js` 파일에 붙여넣어 드립니다.

   이 값(apiKey 등)은 비밀번호가 아니라 "이 프로젝트를 가리키는 주소" 같은 값이라 공개 저장소에 올라가도 괜찮습니다. 실제 접근 제어는 위 3-3의 보안 규칙이 담당합니다.

### 3-5. 동작 확인
- `firebase-config.js`에 값을 채운 뒤에는 `?local=1` 없이 그냥 `index.html`로 접속해도 자동으로 Firebase 모드로 동작합니다.
- 서로 다른 기기(또는 다른 브라우저)에서 방을 만들고 참가해 보면서 실시간으로 반영되는지 확인합니다.

## 4. GitHub Pages로 배포하기 (친구에게 링크로 보내주려면 필요)

**GitHub**은 코드를 저장/공유하는 서비스이고, **GitHub Pages**는 그 코드 중 정적 파일을 무료로 웹사이트처럼 열람 가능하게 해주는 기능입니다.

### 4-1. 저장소 만들기
1. https://github.com 가입/로그인
2. 오른쪽 위 **"+"** → **"New repository"**
3. Repository name 입력(예: `omok-algkagi`) → **Public** 선택 → **Create repository**

### 4-2. 코드 업로드
- 이 단계는 Claude Code가 `git` 명령으로 대신 올려드립니다. (git = 코드 변경 이력을 기록/공유하는 도구, commit = "지금 상태를 저장"하는 행위, push = "내 컴퓨터의 기록을 GitHub 서버로 보내기")

### 4-3. Pages 켜기
1. 저장소 화면에서 **Settings** 탭 → 왼쪽 메뉴 **Pages**
2. **Source**를 **"Deploy from a branch"**로, **Branch**는 **`main` / `/(root)`**로 선택 → **Save**
3. 1~2분 기다리면 화면 위쪽에 `https://(아이디).github.io/(저장소이름)/` 형태의 주소가 표시됩니다.

### 4-4. 확인
- 그 주소로 접속해서 로비 화면이 뜨면 성공입니다.
- `?local=1`이 없으므로 `firebase-config.js`를 채워 넣은 상태라면 자동으로 Firebase 모드로 동작합니다.

## 5. 친구와 대전하기

1. 내 쪽에서 방을 만들고 **"초대 링크 복사"** 버튼을 누릅니다.
2. 복사된 링크(예: `https://아이디.github.io/omok-algkagi/?room=K7PX`)를 친구에게 메신저 등으로 보냅니다.
3. 친구가 그 링크를 열고 닉네임만 입력하면 바로 참가됩니다.

## 6. 알아두면 좋은 제약 (데모 수준)

- **보안**: 로그인이 없어서, 방 코드를 아는 사람은 누구나 그 방에 개입할 수 있습니다. 공개 데모용으로만 사용하세요.
- **렌주 금수 판정**: 3-3/4-4/장목 판정은 일반적인 경우를 정확히 잡아내도록 구현했지만, 아주 드문 복잡한 모양에서는 공식 렌주 심판 기준과 미세하게 다를 수 있습니다.
- **방 정리**: 아무도 없는 오래된 방이 완전히 자동으로 삭제되지는 않고, 같은 코드가 나중에 다시 생성될 때 재사용되는 방식으로 정리됩니다. Firebase 무료 사용량 안에서는 문제가 되지 않습니다.
- **재접속**: 새로고침하면 같은 탭에서는 자기 자리로 돌아오지만, 브라우저를 완전히 껐다가 새로 열면(같은 탭이 아니면) 새로운 사람으로 인식됩니다.

---

## 7. 문제가 생겼을 때

- 화면이 하얗게 안 뜨고 로비가 안 보인다 → 브라우저 개발자 도구(F12) → Console 탭에서 빨간 에러 메시지를 확인
- Firebase 모드에서 상대와 동기화가 안 된다 → Realtime Database의 "규칙" 탭에 `database.rules.json` 내용이 제대로 게시되어 있는지, `firebase-config.js` 값이 정확한지 확인
- 그 외에는 Claude Code에게 증상을 그대로 설명해 주세요.
